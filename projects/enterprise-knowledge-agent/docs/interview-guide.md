# 企业知识库 Agent 面试指南

## 60 秒项目介绍

> 我做了一个可部署的企业知识库与工单 Agent 个人项目。后端使用 Python 和 FastAPI，文档经过解析、切片和向量化后存入 Qdrant，并通过 tenant_id 做企业数据隔离。用户提问时，LangGraph按分类、检索、证据判断、回答或工单升级的流程执行。有充分证据就生成带引用的答案，没有证据就写入 PostgreSQL 人工工单，同时记录执行路径和耗时。项目使用可替换的模型接口，测试使用确定性实现，真实运行可以切换 OpenAI Responses API。整个项目有自动化测试和 Docker Compose 部署文件。

必须称它为个人项目，不要说成真实商业生产项目。

## 架构讲解

请求进入 FastAPI 后，API 层只负责校验和事务边界。文档服务负责解析和切片，向量存储接口负责 Qdrant，模型接口负责生成。LangGraph只编排这些能力，不把所有逻辑塞进一个提示词。

选择显式工作流的原因是企业流程需要可测试、可审计和可控制。模型负责语言理解与生成，证据阈值、租户隔离和工单写入由确定性代码负责。

## 关键取舍

- 使用 Qdrant：展示真实向量数据库和元数据过滤，不用普通列表冒充向量库。
- 使用 LangGraph：问题包含多个步骤和条件分支，图比单次模型调用更清晰。
- 使用 Provider 接口：测试不依赖网络和模型随机性，也能替换模型供应商。
- 低证据转人工：减少幻觉，比强迫模型回答更适合企业场景。
- PostgreSQL 保存工单：关系数据需要事务和明确结构；向量内容放在 Qdrant。

## 项目没有实现的内容

第一版没有实现用户登录、复杂权限、OCR、混合检索、重排模型、生产监控、Kubernetes和高并发压测。当前 `tenant_id` 是数据隔离演示，生产系统还需要从已认证身份中取得 tenant_id，不能直接信任客户端参数。

## 常见追问

### 1. RAG 的完整流程是什么？

加载文档、清洗、切片、Embedding、写入向量库；提问时再次Embedding、相似度召回、按阈值筛选，把有效片段交给模型并返回引用。

### 2. 为什么需要重叠切片？

防止完整语义刚好跨越两个块边界。重叠太大则会增加索引量和重复上下文，需要通过数据评测调整。

### 3. 如何避免跨企业数据泄露？

向量写入时保存 tenant_id，检索时强制服务端过滤，并用自动化测试验证。生产环境还应从登录令牌获取租户身份并加入数据库行级权限。

### 4. 为什么证据不足时创建工单？

企业业务中错误回答的成本可能高于不回答。工单保留用户问题和失败原因，方便人工处理和反向补充知识库。

### 5. Agent 与工作流有什么区别？

Agent允许模型动态决策，工作流预先定义关键路径。本项目使用混合方式：业务路径固定，语言生成由模型完成。

### 6. 如何确定检索阈值？

不能凭感觉固定。应建立包含可回答和不可回答问题的评测集，比较不同阈值下的召回率、误答率和转人工比例。

### 7. OpenAI API 失败怎么办？

设置超时和有限重试；认证错误不重试，限流或临时服务错误采用退避；记录请求 ID 和错误类型，最终返回可恢复错误或转人工。

### 8. 为什么测试不用真实模型？

真实模型有费用、网络依赖和随机输出。单元测试验证工作流与业务规则，模型质量应通过独立评测集验证。

### 9. PostgreSQL 和 Qdrant 分别存什么？

PostgreSQL存工单和执行记录等结构化事务数据；Qdrant存向量、片段文本和检索元数据。

### 10. 如果文档更新怎么办？

生产版应为文档维护版本号，先写入新版本并完成验证，再删除旧版本向量，避免更新过程中出现半完成索引。

## 现场演示顺序

1. 打开 `/docs`。
2. 上传 `employee_handbook.md`。
3. 询问年假，展示答案和引用。
4. 询问班车，展示工单 ID。
5. 查询工单。
6. 展示租户隔离测试和 LangGraph 代码。
7. 运行全部测试。

如果被追问真实用户量，应直接回答这是个人项目，没有虚构用户和生产指标。
